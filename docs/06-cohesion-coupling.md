# Проверка по cohesion / coupling

## Сервис лояльности

Единственная обязанность сервиса — это начисление и списание баллов по правилам программы лояльности. Единственная причина меняться — это изменение правил программы лояльности.

**Риск связанности:** прямое чтение базы данных сервиса заказов, в итоге изменение таблиц сервиса заказов будет требовать изменение сервиса лояльности.

**Как снимаем:** Event-Driven архитектура, после оплаты сервис заказов публикует сообщение в брокер с **фиксированным** контрактом, сервис лояльности подписывается и читает эти сообщения.

## Сервис рекомендаций

Единственная обязанность — это генерация персональных подборок. Единственная причина изменений — измененение рекомендательных моделей или логики ранжирования.

**Риск связанности:** для составления рекомендаций нам необходима история заказов. Может возникунть желание ходить в базу истории заказов напрямую.

**Как снимаем:** решение как выше, сервис слушает события из брокера и наполняет свою собственную базу заказов для формирования рекомендательных моделей.

## Сервис профилей

Сервис управляет только личными данными пользователей. Елинственная причина меняться — это изменение формата данных.

**Риск связанности:** при оформлении заказа сервис заказов будет читать данные профиля, чтобы подставить их при оформлении заказа. 

**Как снимаем:** нам важно, чтобы он не читал напрямую базу профилей, а ходил по одтельному роуту с фиксированным контрактом. В итоге изменения в сервисе профилей на заденут потребителей.

## Сервис истории заказов

Сервис агрегирует данные о заказах и их статусах. У него нет причин меняться кроме изенения логики ранжирования или расширения метаданных.

**Риск связанности:** для отображения истории нам могут потребоваться данные из разных доменов, может появиться соблазн ходить напрямую в каждый такой домен. 

**Как снимаем:** слушаем события из брокера и наполняем свою базу данных.

## Сервис аутентификации

Сервис управляет сессиями и проверками авторизации. Единственная причина меняться — это изменения политик безопасности или добавления/удаление способов авторизации.

**Риск связанности:** другим сервисам будет нужен id пользователя и статус сессии и может возникнуть желание читать таблице сессий напрямую.

**Как снимаем:** внешние сервисы читают данные через строгий контракт без доступа во внутренние особенности сервиса. 

## Сервис поддержки

Сервис обеспечивает создание обращений и передачу их в поддерджку. Единственная причина меняться — изенение логики работы с обращениями или способа их передачи в поддержку.

**Риск связанности:** запрос во внешнюю систему при создании обращения и ожидание ответаб, если система лежит, то создание обрщений в лк не работает.

**Как снимаем:** при создании обращения мы сохраняем его в бд сервиса со статуом принято и публикуем сообщение в брокер. В итоге даже при поломанном внешнем сервисе создание обращений в лк продолжает работать.
